# 2.1 模块与包

> 能正确组织 `go.mod`、import、`internal/` 和依赖版本，而不把 Node.js 包管理习惯硬套到 Go。

## 前置知识

能运行 `go test` 和读懂 import；建议先完成 01 章。

## 正文

### module、package 与文件

`go.mod` 定义 module：一组一起版本化的 Go 包。package 是同一目录中共同编译的一组 `.go` 文件。import path 等于 module path 加包相对路径，而不是磁盘绝对路径。

```text
module example.com/shop
文件 internal/order/service.go（package order）
import path example.com/shop/internal/order
```

与 `package.json` 不同，`go.mod` 不定义脚本、应用元数据或任意配置；`go.sum` 是下载内容的校验记录，不是“精确安装树”的 lockfile。Minimal Version Selection 依据依赖图选择每个 module 的最低满足版本。

module path 应稳定、可全局识别，公开模块通常使用代码托管路径，如 `github.com/acme/shop`。v2 以上主版本需要 `/v2` 后缀。移动本仓库三个子模块的物理目录不影响其 module path，因为内部 import 仍以各自 `go.mod` 为根。

### internal 与可见性

Go 的标识符用首字母大写导出；`internal/` 进一步提供编译器强制的目录边界。`a/b/internal/x` 只能被 `a/b` 树下的代码导入。它不是命名约定，而是真访问控制。

公开 API 越少，兼容承诺越小。业务实现默认放 `internal/`；只有确实要供别的 module 使用时才设计公开包。

### init 的边界

包级变量初始化后，Go 会按依赖顺序执行 `init()`。它无法被直接调用，顺序容易隐蔽，错误也无法返回。只把它用于必须的局部注册或生成代码约定；数据库连接、读取环境、启动 goroutine都应放在显式构造/启动函数中。

### 常用依赖命令

```bash
go get example.com/lib@v1.4.0   # 调整依赖版本
go mod tidy                     # 使 go.mod/go.sum 与 import 一致
go mod download                 # 预下载依赖
go list -m all                  # 查看构建列表
go mod why -m example.com/lib   # 解释为何需要依赖
go mod vendor                   # 生成 vendor 快照
```

`replace` 适合本地多模块开发、临时 fork 或迁移，不能掩盖错误的长期发布路径：

```go
replace example.com/lib => ../lib
```

replace 只影响当前主模块，不会作为下游使用者的全局重定向。

### 私有模块、代理和 vendor

`GOPROXY` 指定模块代理链；`GOPRIVATE=github.com/acme/*` 告诉 Go 私有路径不要走公共 proxy 与 checksum database，并让 Git 凭据负责访问。不要把 token 写进 `go.mod`。

通常使用 module cache 即可。vendor 适合离线/受控构建、供应链审计或组织明确要求；启用后用 `go mod vendor` 机械生成，不手改。它增加仓库体积和同步责任，并不天然更安全。

### 前端人容易踩的坑

- 把 package 等同 npm package；Go package 粒度通常更小，module 才是版本单位。
- 把 `go.sum` 当可随意删除的缓存；它是供应链完整性记录。
- 用相对 import；module 模式应使用完整 import path。
- 到处用 `init()` 做依赖注入，造成不可测的隐式全局状态。
- 为所有目录创建 package；目录应围绕内聚行为，而不是文件分类。

## 对比前端

| Node.js | Go |
|---|---|
| `package.json` | `go.mod` 仅负责 module 与依赖 |
| lockfile 精确依赖树 | `go.sum` 校验内容，MVS 选择版本 |
| `exports` 控制入口 | 大写导出 + `internal/` 编译边界 |
| npm scripts | Makefile/Taskfile/CI（非 go.mod 职责） |
| workspace link | `go work` 或临时 `replace` |
