# 1.1 类型与接口

> 建立从 TypeScript 类型系统到 Go 值语义、方法集和隐式接口的准确映射。

## 前置知识

会写 TypeScript 类型、对象和泛型即可。标注 `package main` 的完整示例可保存为 `main.go` 后执行 `go run main.go`；其余代码块是可嵌入程序的局部片段。

## TypeScript 迁移地图

| 熟悉的 TS 概念 | 本篇先建立的 Go 映射 |
|---|---|
| `number` / UTF-16 string | 明确位宽数字、byte、rune 与 UTF-8 string |
| `undefined \| null` | 零值、`*T` 与 `(T, bool)` |
| 对象引用 | struct 值复制与显式指针身份 |
| `implements` / `unknown` | 隐式小接口、`any`、type switch |
| 泛型约束 | type set 与 `comparable` |

## 正文

### 基础类型与零值

Go 的 `int` 位宽随平台，`int64` 明确为 64 位；`byte` 是 `uint8`，`rune` 是 `int32`，用来表示 Unicode code point。TS 的 `number` 同时承担整数和浮点数角色，Go 则要求显式选择 `int`、`float64` 等类型。

变量声明后一定有零值：数字为 `0`，布尔为 `false`，字符串为 `""`，指针、slice、map、channel、函数和接口可为 `nil`。Go 没有 TS 中 `undefined` 与 `null` 的双重语义。需要表达“未提供”时，可用 `*T`、`(T, bool)` 或显式 Option 类型；不要拿合法零值冒充缺失值。

```go
package main

import "fmt"

func main() {
	var count int
	var name string
	var enabled bool
	fmt.Printf("%d %q %t\n", count, name, enabled)
}
```

### struct 是值，指针才共享身份

TS 对象赋值复制引用；Go 的 struct 赋值复制整个值。slice、map 字段虽然随 struct 一起复制，但它们仍指向共享的底层数据。

```go
package main

type User struct{ Name string }

func main() {
	a := User{Name: "Ada"}
	b := a
	b.Name = "Grace" // a.Name 仍是 Ada

	c := &a
	c.Name = "Linus" // 修改 a
}
```

方法需要修改接收者、接收者较大或包含锁时使用 `*T`；小型不可变值常用 `T`。保持同一类型的方法接收者风格一致。方法集规则很关键：`T` 的方法集只含值接收者方法，`*T` 的方法集同时含值和指针接收者方法，所以只有 `*T` 能满足声明了指针接收者方法的接口。

### 接口是行为集合

Go 不写 `implements`。只要方法集匹配就实现接口，这让实现包不必依赖接口包。接口通常由调用方定义，并保持很小。

```go
type Loader interface {
	Load(id string) ([]byte, error)
}

type CachedLoader interface {
	Loader
	Invalidate(id string)
}
```

`any` 是 `interface{}` 的别名，能装任何值，但会把类型检查推迟到运行期。业务边界优先用具体类型或小接口。

接口值内部包含“动态类型 + 动态值”。只有两者都为空时，接口才等于 `nil`：

```go
type Problem struct{}
func (*Problem) Error() string { return "problem" }

func bad() error {
	var p *Problem
	return p // 动态类型是 *Problem，因此返回值 != nil
}
```

避免返回可能为 nil 的具体指针作为接口；直接在分支中 `return nil`。

### 泛型、断言和 type switch

泛型适合容器、算法和“不同类型但操作完全相同”的代码，不适合隐藏业务差异。

```go
func Contains[T comparable](items []T, want T) bool {
	for _, item := range items {
		if item == want { return true }
	}
	return false
}

func Describe(v any) string {
	switch x := v.(type) {
	case string:
		return "string: " + x
	case fmt.Stringer:
		return x.String()
	default:
		return fmt.Sprintf("%T", v)
	}
}
```

单次断言使用 `x, ok := v.(T)`，不要在不可信输入上使用会 panic 的 `x := v.(T)`。

### 前端人容易踩的坑

- 把 struct、数组当成引用；实际上赋值和传参默认复制。
- 以为 `nil` 能赋给所有类型；`int`、`string`、struct 不能为 nil。
- 把 `any` 当成 TS 的灵活对象，结果到处做运行时断言。
- 在实现方定义大接口；更好的做法是调用方声明所需的 1～3 个方法。
- 忽略 typed nil，出现 `err != nil` 却打印出空指针错误的现象。

## 对比前端

| TypeScript | Go | 关键差异 |
|---|---|---|
| `number` | `int` / `int64` / `float64` | Go 不隐式混算 |
| 对象 | struct 或 `*struct` | struct 默认值语义 |
| `implements` | 隐式接口满足 | 无声明关系 |
| `unknown` | `any` + type switch | 运行期检查 |
| `T \| null` | `*T` 或 `(T, bool)` | 零值不等于缺失 |
