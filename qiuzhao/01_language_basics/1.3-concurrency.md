## 正文

### goroutine 不是 async function

Node.js 的 JS 通常在一个事件循环线程上协作执行；goroutine 是由 Go runtime 调度的轻量执行单元，可并行运行在多个 OS 线程上。`go f()` 只负责启动，不自动收集返回值、错误或生命周期。

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func callProvider(context.Context) error { return nil }

func main() {
ctx, cancel := context.WithTimeout(context.Background(), time.Second)
defer cancel()

result := make(chan error, 1)
go func() { result <- callProvider(ctx) }()

select {
case err := <-result:
	fmt.Println("done", err)
case <-ctx.Done():
	fmt.Println("timeout", ctx.Err())
}
}
```

结果 channel 设为 1，确保调用者超时返回后，发送方仍能结束。每启动一个 goroutine，都要回答：谁等待它、谁让它退出、错误去哪里？

### channel 和 select

无缓冲 channel 的发送与接收同步会合；有缓冲 channel 允许在容量内解耦，但容量满后仍阻塞。缓冲不是“越大越快”，而是队列和背压策略。

函数签名用 `<-chan T` 限制只读，用 `chan<- T` 限制只写。通常由发送方关闭 channel；关闭是“不会再有值”的广播，不能用来发送一条业务事件。接收方用 `v, ok := <-ch` 或 `for v := range ch` 识别关闭。

`select` 同时等待多个 channel；`default` 会把它变成非阻塞尝试，循环中滥用会造成 CPU 忙等。

### 共享状态与同步原语

- `sync.Mutex`：保护一个需要原子更新的不变量。
- `sync.RWMutex`：读远多于写且已通过 profile 证明有收益时使用。
- `sync.Once`：只执行一次初始化；不要把可失败、需重试的远程初始化藏进去。
- `sync.WaitGroup`：只等待完成，不传播错误或取消。
- `atomic`：适合简单计数/标志，不适合多字段业务不变量。

锁保护的是数据约束，不是代码行。不要复制包含 mutex 的 struct；加锁期间避免网络 I/O。

### context 是取消树

`context.Context` 作为第一个参数逐层传递，不存进长期 struct，不传 nil。它携带 deadline、取消信号和请求范围的小型元数据。value 不应承载可选配置或业务参数。

```go
func Fetch(ctx context.Context, client *http.Client, url string) error {
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
	if err != nil { return err }
	_, err = client.Do(req)
	return err
}
```

### 典型故障

- data race：两个 goroutine 并发读写同一内存，使用 `go test -race ./...` 发现。
- 泄漏：goroutine 永久等 channel、锁或无 deadline 的 I/O。
- 死锁：所有 goroutine 都在等待不可能发生的操作。
- send on closed channel：关闭权不清。
- loop variable/captured state：并发闭包共享了不该共享的可变值。

生产者—消费者用有界 channel；并发请求合并可让多个调用者等待同一个 in-flight 结果；超时控制应从入口 context 一直传到网络调用。

### 前端人容易踩的坑

- 把 `go fn()` 当成不需要管理的 Promise。
- 认为 map 像 JS Map 一样可随意并发读写；普通 Go map 并发写不安全。
- 用大 buffer 掩盖慢消费者，最终把延迟转成内存压力。
- 只取消父 context，却让下游函数忽略 `ctx.Done()`。

## 对比前端

| Node.js | Go |
|---|---|
| Promise/await 收集结果 | channel、WaitGroup 或 errgroup 显式收集 |
| AbortController | context 取消树 |
| 单 JS 线程减少数据竞争 | 多线程并行，必须同步共享内存 |
| queue 库控制任务量 | 有界 channel + worker pool |
