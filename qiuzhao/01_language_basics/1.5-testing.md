## 正文

### go test 的基本契约

测试文件以 `_test.go` 结尾，测试函数签名为 `func TestXxx(t *testing.T)`。同包测试可访问未导出标识符，`package foo_test` 黑盒测试只能使用公开 API。优先让失败信息说明 want、got 和输入。

```go
package estimate

import "testing"

func estimate(s string) int { return (len(s) + 3) / 4 }

func TestEstimatedTokens(t *testing.T) {
	tests := []struct {
		name string
		input string
		want int
	}{
		{"empty", "", 0},
		{"four chars", "abcd", 1},
	}

	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			got := estimate(tt.input)
			if got != tt.want { t.Fatalf("estimate(%q)=%d, want %d", tt.input, got, tt.want) }
		})
	}
}
```

表格测试适合一个行为的多组输入。`t.Run` 提供独立名称与生命周期。只有用例完全隔离时才调用 `t.Parallel()`；共享全局、端口、环境变量或数据库时要格外谨慎。

### 断言库和测试替身

标准库 `if got != want { t.Fatalf(...) }` 依赖少、错误意图清晰；testify 适合团队已统一并需要集合/错误辅助函数时。不要为了缩短一行而隐藏比较语义。

替身选择由边界决定：

- 小接口 fake：验证业务决策，快速且确定。
- `httptest.NewRecorder`：直接测 handler；`httptest.NewServer`：测真实 HTTP client/server 交互。
- 内存实现：测试 repository/event store 的契约。
- mock：必须验证调用协议时再用，避免对内部调用次数过度耦合。

```go
req := httptest.NewRequest(http.MethodGet, "/healthz", nil)
rec := httptest.NewRecorder()
handler.ServeHTTP(rec, req)
if rec.Code != http.StatusOK { t.Fatalf("status=%d", rec.Code) }
```

### benchmark、fuzz 和覆盖率

```go
func BenchmarkRoute(b *testing.B) {
	r := newRouter()
	b.ReportAllocs()
	for i := 0; i < b.N; i++ { _, _ = r.Select("default") }
}

func FuzzDecode(f *testing.F) {
	f.Add([]byte(`{"name":"ok"}`))
	f.Fuzz(func(t *testing.T, data []byte) {
		_, _ = decode(data) // 目标：任意输入不 panic
	})
}
```

运行：`go test ./...`、`go test -race ./...`、`go test -cover ./...`、`go test -bench=. -benchmem ./...`、`go test -fuzz=FuzzDecode`。覆盖率只说明哪些语句执行过，不说明断言是否有价值；优先覆盖风险、边界和失败路径。

### 前端人容易踩的坑

- 把每个依赖都 mock，测试只是在复述实现。
- 直接比较含 map 的 struct 或依赖 map 迭代顺序。
- 随意 `t.Parallel`，引入共享状态 race。
- 用 sleep 等 goroutine，造成慢且偶发失败；应使用 channel、fake clock 或明确同步点。
- 只追逐覆盖率百分比，不测超时、取消、满队列和错误包装。

## 对比前端

`go test` 同时承担 Jest/Vitest runner、benchmark 和 fuzz 入口。Go 没有默认 `expect` DSL，表格测试比 `describe.each` 更直接。接口通常很小，因此手写 fake 往往比自动 mock 简单；`httptest` 对应 Supertest 的常见用途，但直接使用标准 HTTP 类型。
