# 3.2 中间件与管道

> 能区分洋葱中间件、责任链与数据管道，并为每种组合方式选择正确接口。

## 前置知识

理解 `net/http` 的 `http.Handler` 和函数类型。

## 正文

### 洋葱模型

Go HTTP middleware 是高阶函数：接收并返回 `http.Handler`。请求按外到内进入，响应/`defer` 按内到外退出。

```go
type Middleware func(http.Handler) http.Handler

func RequestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := newID()
		ctx := context.WithValue(r.Context(), requestIDKey{}, id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}
```

`Recover(Log(Timeout(Auth(handler))))` 的顺序就是语义：Recover 只能捕获其内层 panic；日志若要观察认证拒绝必须位于 Auth 外；timeout 要覆盖哪些工作也由位置决定。

### Endpoint 装饰器

业务 endpoint 可避开 HTTP 类型：

```go
type Endpoint func(context.Context, Request) (Response, error)
type Middleware func(Endpoint) Endpoint
```

认证、限流、指标若依赖领域请求，应放 endpoint 中间件；header、CORS、压缩属于 HTTP 中间件。不要让一个 middleware 同时理解所有层。

### 责任链和 pipeline

责任链让 processor 依次尝试，某个节点可以处理、拒绝或传给下一个，适合策略/路由链。数据 pipeline 则让每个 stage 明确转换输入输出，适合 OTel 的 receiver → processor → exporter。

```go
type Stage[I, O any] func(context.Context, I) (O, error)

func Run[A, B, C any](ctx context.Context, in A, ab Stage[A, B], bc Stage[B, C]) (C, error) {
	b, err := ab(ctx, in)
	if err != nil { var zero C; return zero, err }
	return bc(ctx, b)
}
```

异步 stage 之间加 channel 会引入队列容量、顺序、失败、重试和关闭协议；没有吞吐或隔离需求时优先同步函数组合。

### 真实项目提取

- Tyk：请求穿过认证、配额、限流、变换、代理和分析；重点是阶段顺序及短路语义。
- OpenTelemetry Collector：receiver/processor/exporter 有稳定组件契约，pipeline 由配置组装。
- Caddy：模块通过 ID/namespace 注册、配置解码和生命周期加载；可提取“registry + config + provision/cleanup”，而不是复制全局插件体系。

### 前端人容易踩的坑

- 照搬 Express `next(err)`，忽略 Go 返回值和 `defer` 已能表达退出路径。
- middleware 偷改业务实体，边界职责不清。
- 把所有 stage 都做成 goroutine/channel，增加关闭和背压复杂度。
- 责任链中吞掉错误，调用方无法区分“不处理”和“处理失败”。

## 对比前端

Express middleware 通过 `next()` 前进，Koa 的 `await next()` 最接近 Go 的洋葱模型；Go 用函数包装表达相同结构，不需要框架协议。Go pipeline 还可借静态类型限制每个 stage 的输入输出，异步边界则必须显式设计 channel 生命周期。
